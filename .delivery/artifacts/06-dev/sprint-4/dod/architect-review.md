Role: Solution + Security architect, read-only. Scope: ADR-001..007, EPICS A-4/E-4, docs/SSRF.md.
Method: `git archive 9d3dc21` to /tmp/arch, offline `--locked` build, `cargo test --locked` (135 lib + 9 integration passed, 1 ignored bench test),
`cargo deny check` (advisories, bans, licenses, sources: ok), `scripts/check-release-features.sh` and `--self-test` (both OK).

## Decision: NOT_DONE (2 blocking)

## Blocking

### B1. Drop rules silently switch off below 256 open elements (script/style/iframe/nav text reaches the model)
Reproduced at head: `"<div>"*256 + "<script>SECRET_JS()</script><style>.x{}</style><iframe>IFR</iframe><nav>NAV</nav><p>body</p>"` outputs
`SECRET_JS().x{}IFRNAVbody`. At depth 10 and 255 it outputs `body`. Cause: `Md::start` returns at `if self.open >= OPEN_CAP && !void`
(src/convert/markdown.rs, before the "drop rules" block), so DROP_TAGS, hidden attributes and noise classes are never applied past the cap.
The landmark check is behind the same return. This contradicts the module contract, ADR-002 tier 1 and the A-4 statement that script/style/iframe are stripped,
and it lets an attacker put arbitrary text in the "stripped" classes into the LLM context with 256 nested `<div>`s. The same finding is recorded in
`.delivery/artifacts/06-dev/sprint-4/pr-review/pr8-code-review.md` and is NOT fixed at 9d3dc21 (not listed under the dev report's honest gaps).
Fix direction: evaluate drop rules (and the landmark start) before the depth cap; skips are not counted in `open`, so the cap is not weakened. Add a regression at OPEN_CAP+1 for script, style, iframe, nav. Consider failing closed (`converter_limit`) rather than degrading when depth exceeds the cap.

### B2. The 2 MiB lol_html limit does not bound real memory: one hostile start tag costs ~110-140 MB (vs the 40 MiB gate and the 5.1 budget of 2 MiB for row f)
Probe: `<div ` + N x `"a "` (many tiny attributes, tag completed, total under 2 MiB) then `>x</div>`, fed in 16 KiB slices, release profile (opt-level s):

| attribute bytes in tag | peak RSS of the probe process (baseline 3 MB) | result |
|---|---|---|
| 160 KiB | 14 MB | ok |
| 480 KiB | 36 MB | ok |
| 1.0 MiB | 69 MB | ok |
| 1.6 MiB | 114 MB | ok, no `converter_limit` |
| 1.6 MiB, tag left open | 43 MB | ok |
| unterminated `<a <a <a ...` tags | 37 MB | `Limit` (after the transient) |

Roughly 70 bytes of heap per input byte: lol_html's attribute outline vector (48 B per attribute, counted nowhere in `max_allowed_memory_usage`) plus `Attrs::read`, which calls `el.attributes()` on every element and so materialises a name and value allocation for every attribute (the `*` element handler runs for every tag). At the full 2 MiB the projected cost is ~140 MB per fetch, and up to `FETCH_MAX_CONCURRENCY` (3) fetches can do it at once, against a 40 MiB peak target (NFR) and the architecture 5.1 arithmetic (10 + 3 x 6.3 MiB). A page can therefore defeat the memory promise (and OOM a container limit) at no cost to the attacker. The converter doc claims "memory is bounded whatever the page size or shape"; the unit tests only assert the `Limit` result on hostile inputs, not RSS, and the G4a scenario set contains no hostile shape, so CI cannot see it. Other hostile shapes I ran (100 MiB of paragraphs/text/entities, deep nesting, big class/href, table floods, unclosed anchors, 30,000 random token-soup documents in release mode, chunked at random sizes) stayed at 3-5 MB RSS, returned `Limit` fast, and never panicked; only attribute-dense tags escape the budget.
Fix direction (owner of the design decides): cap what one tag may cost, for example a much lower `max_allowed_memory_usage` (a 128-256 KiB tokenizer buffer bounds this at roughly 9-18 MB) with the ADR-002 flip rule re-measured, and/or avoid bulk `el.attributes()` (use targeted lookups) if lol_html permits; then add an RSS-asserting hostile case (attribute flood) to the tests or a bench scenario, and re-state 5.1 row f with the measured amplification factor.

## Non-blocking

1. New dependencies (necessity): lol_html is justified by ADR-002 and the A-1 spike (buffered DOM converters 56-185 MiB); html-escape replaces a 2125-entry table. Direct-dependency count 10 of 15 (NFR-05) holds. The lock adds ~30 transitive crates, several proc-macro/build-time: cssparser-macros, phf_macros (+phf_generator, fastrand, siphasher), derive_more-impl, multiversion-macros (pulls syn 3.0.6 next to syn 2.0.119, a `multiple-versions` warning), rustversion, plus encoding_rs, hashbrown 0.17, foldhash, mime, selectors, servo_arc, precomputed-hash, new_debug_unreachable, simdutf8. Most of it exists only to serve lol_html's CSS selector engine, which this converter uses only as `*`. Build-time code execution and unsafe surface grew; `cargo deny advisories` is clean today, and `cargo vet`/audit review of these is not in place.
2. Maintenance: lol_html is Cloudflare's (active, MSRV 1.85, BSD-3-Clause), 2.9.0 is one major behind 3.0.1. Pin is deliberate (spike measured 2.9.0). I could not inspect 3.0.1's tree offline; the re-measure plus the lockstep of any changed MPL crates is the cost of moving. html-escape 0.2.15 (MIT, single maintainer, low churn) contains `unsafe` (`from_utf8_unchecked` over its own output buffers, 12 sites in decode/encode paths); fed with hostile text/attributes by design. 30,000 fuzz documents plus the entity floods produced no fault; residual risk is low, but the unsafe is not covered by the repo's tests except via this path. lol_html itself has 4 `unsafe` sites.
3. MPL-2.0 facts (OQ-7 is owner-open; not resolved here). Four crates carry MPL-2.0 and nothing else in the lock does (cargo-deny passes with exactly these four exceptions, so the list is minimal in the current tree): cssparser 0.36.0, cssparser-macros 0.6.1 (a proc-macro, compile-time only, not linked into the binary), dtoa-short 0.3.5, selectors 0.37.0. MPL-2.0 is file-level weak copyleft: (a) unmodified use as crates.io dependencies does not extend MPL to this crate's own files; the Apache-2.0 LICENSE and any OQ-7 choice remain possible (it is a "Larger Work", MPL-2.0 s3.3); (b) modifying any covered file obliges publishing those modifications under MPL-2.0 (patching or vendoring a fork would trigger it); (c) distributing the Executable Form (the statically linked binary, hence the GHCR image, `strip`/LTO do not change this) requires telling recipients how to obtain the Source Form of the covered crates (s3.2: exact crate names and versions, for example a pointer to crates.io and the Cargo.lock), and preserving copyright/licence notices (s3.4); there is no obligation to release this project's source because of them; (d) MPL-2.0 s2/s5 patent grant and termination apply to the contributors of those files. Practical consequence for D-6/D-2: a THIRD-PARTY notice with licence texts in the image or repo, which the dependency audit story (D-6) must add anyway (webpki-roots CDLA-Permissive-2.0, encoding_rs BSD-3-Clause part). The exceptions in deny.toml name crates without versions, so a future selectors/cssparser major is silently accepted; pin them (`cssparser@0.36`). Alternatives to avoid MPL entirely: ADR-002 option C (html5gum tokenizer, permissive, more own code, unmeasured, already "kept as fallback behind the trait"), a hand-written tokenizer, or lol_html 3.x if its tree drops the selector crates (unverified). The `Converter` trait makes a swap local.
4. Output injection (consistent with OQ-5 "no label", so a documentation issue rather than a defect): text is emitted unescaped. Page text `[fake](http://evil)`, `![p](http://evil/x.png)`, a paragraph starting with `# ` or a triple backtick, and a `]` inside link text all pass through verbatim and render as real markdown links, headings or fences to a markdown-aware client; an inline `<code>` with a backtick breaks out of its span. Link destinations are handled well: only http, https, mailto, tel survive (javascript:, JaVaScRiPt:, entity-encoded and tab-split variants, data:, vbscript:, file:, ftp: all lose the link and keep text), parentheses and `<>` are encoded, and a `)](http://evil)` inside a query is percent-encoded; images need alt and an http(s) src, alt brackets are stripped. `<pre>` fences are guarded against embedded fences. ESC (ANSI/OSC-8), bidi override (U+202E) and other C0 controls other than NUL pass through unchanged, a terminal-escape risk for clients that print tool output. No content label or notice is added anywhere (grep for notice/untrusted: only the doc comment); only the FR-14 `URL:`/`Status:` header on redirects, which uses `echo_url` (no userinfo, no fragment). PRD Risk 5 should keep stating that untrusted output is not neutralised.
5. Stripping only applies to HTML the converter recognises: a missing Content-Type is sniffed only for `<!doctype html`, `<html`, `<head`, `<body` in the first 16 chars, so an untyped body starting with `<script>` or `<p>` is returned raw (verified). Rejection and full sniffing are A-6.
6. No early stop yet (A-5/G4b): `Window::push` keeps iterating the rest of the converted output and the body is read to the 50 MiB cap; memory is flat (100 MiB stream: 3.8 MB RSS, 0.5 s) but CPU/time are spent after the window is full. `converter_limit` path is sound: failure is parked, checked per chunk and at finish, the connection is dropped on error, the message is static (no page content), `raw=true` bypasses the converter. `push` after `fail` returns `Err`. No panic under panic=abort in release or in the random-token soup; there is no unwrap/index on input and `println!` is denied by lint; stdout purity is covered by tests/stdio.rs (passed).
7. build.rs / `--version`: deterministic (no timestamps, host paths or network; `git rev-parse` only), no new dependency, handwritten SHA-256 cross-checked against `sha256sum` in a lib test. Gaps: a dirty tree is not marked (the commit alone can mislead), refs that get packed are not tracked by `rerun-if-changed` (stale commit possible in incremental builds; build-candidates.sh compares against `git rev-parse` and fails closed), `FETCH_MCP_COMMIT` is not validated (a `git archive`/Docker context without .git yields `unknown`, which the 40-hex check in build-candidates.sh rejects, so D-1 must pass the env var). Only Cargo.lock is hashed, not the toolchain.
8. Release guard and merge gate: `.github/workflows/ci.yml`, `scripts/check-release-features.sh` and the a3b tests are unchanged in the diff; guard and self-test pass on the new tree; job names (fmt, clippy, test, deny, release-guard, a3b-merge-gate, bench-gate x4) and thus the required-check set are unchanged; docs/ci-branch-protection.md only edits prose and states so. The guard checks only root-package features, not dependency features (lol_html is `default-features = false`).
9. CI workflow security: bench.yml keeps `permissions: contents: read`, no `pull_request_target`, no secrets, pinned checkout SHA, fork PRs skipped, `persist-credentials: false`. New steps: a `cargo test --release ... --ignored` timing step (local code only) and the advisory public-host step, which makes the runner fetch a live Wikipedia page nightly (network egress, non-deterministic, `continue-on-error`, failure `reason` up to 200 chars of server output is echoed into the job summary; low risk). `build.rs` is added to the PR path filter. deny.toml warns of two unused licence allowances (BSD-2-Clause, CC0-1.0) and duplicate syn versions; cosmetic.
10. ADR-002 tier 2 (link-density rule) is knowingly not implemented (dev report); ADR-002 is still "Proposed" while the code implements it; status should be moved to Accepted or amended when B1/B2 are settled (limit value, cap behaviour).
